День 1 · Подготовка

Подключить компьютер к GitLab

Цель: создать SSH-ключ и добавить его в GitLab.

  1. Открой терминал.

  2. Проверь, есть ли уже ключ: ls ~/.ssh — если видишь id_ed25519, шаг 3 пропускай.

    + Пример: как понять вывод 
    $ ls ~/.ssh
id_ed25519  id_ed25519.pub  known_hosts

    Видишь id_ed25519 — ключ уже есть, иди к шагу 4. Папки нет или пусто — делай шаг 3.

  3. Создай ключ, на все вопросы жми Enter: ssh-keygen -t ed25519

  4. Покажи ключ и скопируй всю строку целиком: cat ~/.ssh/id_ed25519.pub

    + Пример: как выглядит ключ 
    ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIOMqqnkVzrm1bidsMPky3Z user@pc

    Одна длинная строка от ssh-ed25519 до конца. Копируй её полностью, без пробелов по краям.

  5. В браузере: GitLab → аватарка → Preferences → SSH Keys → Add new key → вставь → Add key.

День 1 · Квест 1

Clone — скачать репозиторий

Цель: получить копию репозитория и создать ветку develop.

  1. Перейди в домашнюю папку: cd ~

  2. Склонируй репозиторий (адрес — кнопка Clone на странице проекта в GitLab, вкладка SSH):

    git clone ssh://git@git-ssh.21-school.ru:2222/students_repo/твой_логин/D01T01_ID_1577481-1.git
    + Пример: первый запуск спросит yes/no — это нормально 
    $ git clone ssh://git@git-ssh.21-school.ru:2222/...
Cloning into 'D01T01_ID_1577481-1'...
The authenticity of host '[git-ssh.21-school.ru]:2222' can't be established.
Are you sure you want to continue connecting (yes/no)? yes

    Напечатай yes и Enter — сервер добавится в доверенные. Дальше скачивание пойдёт само.

  3. Войди в папку репозитория, а затем в рабочую папку src:

    cd D01T01_ID_1577481-1
cd src
    + Структура после клонирования 
    D01T01_ID_1577481-1/
└── src/        ← вся работа здесь

    Почти все команды дальше выполняются внутри src. Проверить, где ты: pwd — путь должен заканчиваться на D01T01_ID_1577481-1/src.

  4. Создай ветку develop и перейди в неё: git checkout -b develop

  5. Проверь: git branch — звёздочка должна быть у develop.

    + Пример: правильный вывод 
    $ git branch
* develop
  master

    Звёздочка * = «ты сейчас здесь». Она у develop — всё верно.

+ Почему так: зачем ветка develop

В master лежит чистая версия, вся работа — в develop. Сломаешь что-то — master не пострадает.

День 1 · Квест 2

Repo — запустить скрипт

Цель: запустить src/ai_initial_module/ai_initial_module.sh (скрипт лежит в папке src/ai_initial_module/), который требует 5 модулей.

  1. Посмотри файлы и права в папке модуля: ls -l src/ai_initial_module/

    + Пример: как читать права 
    -rw-rw---- 1 user user 1234 ... ai_initial_module.sh
 ▲  ▲   ▲   ▲
 │  │   │   └─ остальные: --- (ничего нельзя)
 │  │   └─ группа: rw- (читать, писать)
 │  └─ владелец: rw- (читать, писать)
 └─ тип: - (обычный файл)

    Буквы x нигде нет — запускать запрещено. Поэтому скрипт не стартует.

  2. Дай скрипту право на запуск: chmod +x src/ai_initial_module/ai_initial_module.sh

  3. Проверь: ls -l src/ai_initial_module/ — должно стать -rwxr-xr-x (или хотя бы появилась буква x).

    + Пример: было → стало 
    было:  -rw-rw----   (x нет — не запускается)
стало: -rwxrwx---   (x есть — запускается)

  4. Проверь файл с данными: cat src/ai_initial_module/important_data_for_ai_module_2.txt — в нём должны быть числа 1–5, каждое на своей строке. Если данные повреждены — приведи файл к этому виду.

    + Как должно быть в файле 
    1
2
3
4
5

  5. Запусти: ./src/ai_initial_module/ai_initial_module.sh

  6. Читай, что он пишет, — скажет, чего не хватает.

    + Пример: как выглядит жалоба скрипта 
    [1/5] door module... OK
[2/5] control module... OK
[3/5] config module... FAIL
ERROR: file not found: src/ai_config/door.conf

    Читай буквально: он говорит, какого файла нет и где его ждёт. Создай именно это.

  7. Посмотри его код: cat src/ai_initial_module/ai_initial_module.sh — поймёшь, что он ищет.

  8. Исправь проблемы (создай нужное, дай права) и запускай снова — пока не заработает.

    ⛔ Сам скрипт менять нельзя — чиним только окружение: файлы, папки, права.
    + Пример: вывод рабочего скрипта 
    [1/5] door module... OK
[2/5] control module... OK
[3/5] config module... OK
[4/5] key module... OK
[5/5] log module... OK
ALL MODULES OK

    Добивайся такого вывода. Только потом — коммит.

  9. Зафиксируй:

    git add .
git commit -m "Quest 2: fix modules"
git push origin develop

День 1 · Квест 3

Dirs & Files — починить конфигурацию

Цель: модуль управления дверьми не находит файлы — создать/переименовать нужные, вести журнал.

  1. Вот такая структура папок должна получиться внутри src/:

    door_management_files/
├── door_configuration/   # door_1.conf … door_16.conf + door_21.conf = 17 конфигов
├── door_logs/            # door_1.log … door_16.log = 16 логов
└── door_map/             # door_map_1.1 = 1 карта

    Создать сразу все папки (ключ -p создаёт и родительские):

    mkdir -p door_management_files/door_configuration
mkdir -p door_management_files/door_logs
mkdir -p door_management_files/door_map

    Проверка общего числа файлов: find door_management_files -type f | wc -l — должно быть 34 (17 конфигов + 16 логов + 1 карта).

    Сами скрипты модуля лежат в src/: ai_door_management_module.sh и ai_door_control.sh. Если не запускаются — chmod +x ai_door_management_module.sh ai_door_control.sh.

  2. Запусти модуль: ./src/ai_door_management_module.sh

  3. Он выдаст ошибку. Запиши, что именно он просит.

    + Пример: ошибка называет путь 
    ERROR: config directory not found: src/door_management_files

    Он прямо называет путь — src/door_management_files. Создай именно эту папку и подпапки из шага 1.

  4. Прочитай код: cat src/ai_door_management_module.sh — найди, где и какие имена он ищет.

    + Пример: что искать в коде 
    CONFIG_DIR="src/door_management_files/door_configuration"
CONFIG_FILE="$CONFIG_DIR/door_1.conf"

    Ищи слова CONFIG, DIR, FILE, .conf — там спрятаны нужные папка и имя файла.

  5. Сравни с реальностью: ls src/

  6. Создай недостающую папку (имена — шаг 1): mkdir -p src/door_management_files/нужная_папка, например mkdir -p src/door_management_files/door_logs.

  7. Файл назван не так — переименуй: mv старое_имя новое_имя

  8. Файл есть, но не читается — дай право: chmod +r имя_файла

  9. Каждую команду сразу пиши в журнал:

    echo "mkdir имя_папки" >> src/quest3.sh
echo "mv старое_имя новое_имя" >> src/quest3.sh
    Только две стрелки >> (дописать). Одна > сотрёт файл!
    + Пример: готовый журнал + разница > и >>

    Так выглядит заполненный src/quest3.sh:

    mkdir -p src/door_management_files/door_configuration
mkdir -p src/door_management_files/door_logs
mkdir -p src/door_management_files/door_map
mv src/door1.cfg src/door_management_files/door_configuration/door_1.conf
chmod +r src/door_management_files/door_configuration/door_1.conf

    Каждая строка — твоя команда. Потом журнал можно запустить как скрипт и всё повторится.

    echo "hi" > file.txt    # СТЕРЕТЬ всё, записать hi
echo "hi" >> file.txt   # ДОПИСАТЬ hi в конец

  10. Запускай модуль снова, читай следующую ошибку, исправляй — пока не заработает.

  11. Зафиксируй:

    git add .
git commit -m "Quest 3: fix door config"
git push origin develop

День 1 · Квест 4

Kill him — остановить процесс

Цель: ai_door_control.sh крутится бесконечно — найти и остановить.

  1. Найди процесс: ps aux | grep ai_door_control

    + Пример: что значит команда по частям 
    ps aux  |  grep ai_door_control
   ▲     ▲     ▲
   │     │     └─ оставить строки с этим словом
   │     └─ передать список дальше
   └─ показать ВСЕ процессы

  2. Вторая колонка найденной строки — PID. Запиши число.

    + Пример: где PID и какую строку игнорировать 
    $ ps aux | grep ai_door_control
user  12345  0.0 ...  ./src/ai_door_control.sh   ← ОН, PID = 12345
user  12399  0.0 ...  grep ai_door_control       ← игнорируй, это твой поиск

    Строка с grep — это твоя же команда поиска, её не трогаем.

  3. Останови: kill номер_PID

  4. Проверь: ps aux | grep ai_door_control — строки с процессом нет.

    + Пример: убит / не убит 
    # УБИТ — остался только grep:
user  12410 ... grep ai_door_control

# НЕ УБИТ — строка с .sh на месте, нужен kill -9:
user  12345 ... ./src/ai_door_control.sh

  5. Не умер — жёстче: kill -9 номер_PID

  6. Запиши в журнал:

    echo "ps aux | grep ai_door_control" >> src/quest4.sh
echo "kill номер_PID" >> src/quest4.sh

  7. Зафиксируй:

    git add .
git commit -m "Quest 4: kill door control"
git push origin develop
+ Почему так: kill и kill -9

У каждого процесса есть номер — PID. Обычный kill — вежливая просьба завершиться, kill -9 — принудительное убийство без вопросов.

День 1 · Квест 6

Rm — собрать ключ из файлов

Цель: оставить только фрагменты ключа и собрать их в main.key.

  1. Дай права: chmod +x src/ai_help/*.sh

  2. Запусти генератор: ./src/ai_help/keygen.sh — появится папка с кучей файлов.

  3. Посмотри на них: ls src/ai_help/ (или ls в созданной папке).

    Посчитай ключи: find src/ai_help -name "*.key" | wc -l — в нашем варианте получилось 60. Лишние файлы (не .key) удали — см. шаг ниже.

  4. Прочитай скрипт сборки: cat src/ai_help/unifier.sh — узнай расширение (например .key) и содержимое, которое он ждёт.

    + Пример: как понять unifier.sh 
    cat ./*.key > main.key

    Расшифровка: «склей все файлы .key из папки ai_help в main.key». Значит, всё остальное — мусор под удаление.

  5. Подсмотри содержимое: head имя_файла — фрагменты ключа отличаются от мусора.

    + Пример: ключ vs мусор 
    # фрагмент ключа — похож на случайный набор символов:
a3f9c1d2e7b4a9c0d3f8e1b6a5c4

# мусор — всякий хлам:
error_log_2024.txt, tmp_xxx, README

  6. Удали мусор: по одному rm имя_файла или массово:

    find путь_к_папке -type f ! -name "*.key" -delete
    Сначала запусти без -delete — посмотри список. Потом с -delete. Расширение сверь с шагом 4!
    + Пример: безопасное удаление + разбор команды 
    # 1. СМОТРИМ, что попадёт под удаление:
find src/ai_help -type f ! -name "*.key"

# 2. Всё верно? Тогда удаляем:
find src/ai_help -type f ! -name "*.key" -delete

    -type f = только файлы, ! -name "*.key" = «НЕ с именем .key». Итого: «удали всё, кроме .key».

  7. Собери ключ: ./src/ai_help/unifier.sh — при успехе он печатает Ok. и создаёт main.key в папке src/ai_help/.

  8. Проверь результат: cat src/ai_help/main.key — внутри число (в нашем варианте получилось 694; у тебя может быть своё — главное, что main.key собран твоим unifier.sh).

    + Пример: правильная проверка 
    $ ls src/ai_help/
keygen.sh  unifier.sh  main.key  (+ файлы .key)

$ cat src/ai_help/main.key
694

  9. Все команды запиши в журнал: echo "команда" >> src/quest6.sh — каждую своей строкой.

  10. Зафиксируй:

    git add .
git commit -m "Quest 6: build main.key"
git push origin develop

+ Свериться: точные ветки, файлы и порядок слияний

Должны существовать ветки: develop, key-branch, feature/3-key, release/1.0 (и master). Ключи лежат в папке src/ai_help/.

git checkout develop
git checkout -b key-branch
cp ai_help/main.key ai_help/main-2.key
git add ai_help/main-2.key
git commit -m "key-branch: add main-2.key"

git checkout -b feature/3-key
cp ai_help/main.key ai_help/main-3.key
git add ai_help/main-3.key
git commit -m "feature/3-key: add main-3.key"

git checkout key-branch
git merge feature/3-key        # Fast-forward — это нормально

git checkout develop
git checkout -b release/1.0
git checkout develop
git merge key-branch           # Fast-forward
git checkout release/1.0
git merge develop

Имя ветки стоит в начале сообщения коммита: key-branch: ... и feature/3-key: .... В конце нужно оказаться на release/1.0 с чистым деревом, проверить: git log --oneline --graph --all --decorate -10.

+ Почему так: что такое ветка

Ветка — «параллельная версия» проекта. Работаешь в ней — основную не трогаешь. Так люди (или ты в разных задачах) не мешают друг другу.

Подготовка и общие правила

Цель: склонировать репозиторий дня 2 и запомнить правила.

hello.c — первая программа

Цель: программа печатает Hello, AI!

  1. Создай файл: nano src/hello.c

  2. Вставь код:

    #include <stdio.h>

int main(void) {
  printf("Hello, AI!");
  return 0;
}

  3. Сохрани: Ctrl+O, Enter, Ctrl+X.

    $ ./hello

    rm hello
git add src/hello.c
git commit -m "Quest 1: hello"
git push origin develop
+ Разбор кода построчно

#include <stdio.h> — подключить библиотеку, где живёт printf (печать).

int main(void) — точка входа, отсюда стартует программа.

return 0 — «завершилась успешно». В printf нет \n — автотесты сверяют вывод посимвольно.

День 2 · Квест 2

named_hello.c — ввод имени

Цель: прочитать целое число и поздороваться с ним.

  1. Создай: nano src/named_hello.c

  2. Код:

    #include <stdio.h>

int main(void) {
  int name;
  char extra;

  if (scanf("%d %c", &name, &extra) != 1) {
    printf("n/a");
    return 0;
  }
  printf("Hello, %d!", name);
  return 0;
}
    + Пример: как ловушка %c ловит мусор 
    ввод "123"  → прочитал (123), extra пусто → вернул 1 → Hello, 123!
ввод "abc"  → число не прочитал          → вернул 0 → n/a

+ Разбор: scanf, %d, &

scanf читает с клавиатуры. %d = целое число. & перед переменной = «адрес ящика, куда положить».

Хитрость с %c: он читает символ даже после числа. Если там был мусор — scanf вернёт 2 вместо 1, и мы выведем n/a.

float_compare.c — эпсилон

Цель: файл уже есть — починить в нём сравнение с нулём.

  1. Посмотри файл: cat src/float_compare.c

  2. Найди fun() — она возвращает (1.0/13) * (1/3)^20 ≈ 0.000000000022. Это НЕ ноль!

    + Пример: почему == не работает для дробей 
    double r = 0.1 + 0.2;
printf("%d", r == 0.3);   // напечатает 0, то есть ЛОЖЬ!
// потому что r = 0.30000000000000004, а не 0.3

    Дроби хранятся приближённо. Поэтому условие res == 0 никогда не срабатывает и OK! не печатается.

  3. Открой: nano src/float_compare.c

  4. Меняй ТОЛЬКО условие (fun не трогать):

    const double kEpsilon = 1e-6;

if (fabs(res) < kEpsilon)
  printf("OK!");
    Если нет #include <math.h> сверху — добавь (нужен для fabs).
    + Пример: было → стало + почему сработает 
    // БЫЛО — не работает:
if (res == 0) printf("OK!");

// СТАЛО — работает:
const double kEpsilon = 1e-6;   // 0.000001
if (fabs(res) < kEpsilon) printf("OK!");

// res = 0.000000000022, эпсилон = 0.000001
// 0.000000000022 < 0.000001 → правда → OK!

    fabs — модуль (убирает минус). Идея: считаем «нулём» всё, что меньше допуска.

  5. Скомпилируй с -lm: gcc -Wall -Werror -Wextra -std=c11 src/float_compare.c -o float_compare -lm
